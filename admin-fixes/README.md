# اصلاح ریشه‌ای «انجام تغییرات» (Apply Config)

نشانه: پس از کلیک روی «انجام تغییرات» در مرکز تلفن، دکمهٔ نارنجی بالای صفحه
برای همیشه می‌ماند و هیچ پیام موفقیت نمایش داده نمی‌شود.

## سه علت ریشه‌ای (هر سه با مرورگر واقعی روی ۱۹۲٫۱۶۸٫۸٫۱۷۱ اثبات شد)

۱. **سمِ تایم‌اوت سراسری داشبورد** — `modules/dashboard/page.index.php`
   این را تزریق می‌کرد: `$.ajaxSetup({timeout:10000})`؛ یعنی مرگِ همهٔ
   درخواست‌های اجکس روی ثانیهٔ دهم. عملیات اعمال تغییرات ۸ تا ۱۵ ثانیه
   طول می‌کشد؛ جی‌کوئری دقیقاً روی ثانیهٔ ۱۰ درخواست را سقط می‌کرد
   (وضعیت صفر) و پیام موفقیت هرگز اجرا نمی‌شد.
۲. **پوسته اجازهٔ مخفی‌شدن نمی‌داد** — `assets/mytel/skin.css` روی دکمه
   `display: inline-flex !important` گذاشته بود؛ استایلِ مهمِ صفحه همیشه
   بر استایل درون‌خطی جی‌کوئری (`hide()`) غلبه می‌کرد؛ پس دکمه هرگز
   مخفی نمی‌شد.
۳. **بازخورد موفقیت وجود نداشت** — رفتار رسمی فقط مخفی‌کردن دکمه است؛
   کاربر فارسی‌زبان هیچ «با موفقیت انجام شد»ای نمی‌دید.

## اصلاحات

| فایل | تغییر |
|------|-------|
| `modules/dashboard/page.index.php` | حذف تایم‌اوت سراسری؛ تایم‌اوت ۱۰ثانیه‌ای فقط روی دو نظرسنجی خودِ داشبورد |
| `assets/js/pbxlib.js` | تایم‌اوت صریح ۱۲۰ثانیه‌ای برای درخواست `handler=reload` — مصون از هر سم آینده |
| `assets/mytel/skin.css` | `#button_reload` پیش‌فرض مخفی؛ فقط وقتی سرور «نیاز به بازخوانی» علامت بزند نمایش می‌یابد |
| `assets/mytel/sub.js` | اعلان سبز فارسی «تغییرات مرکز تلفن با موفقیت اعمال شد» پس از پاسخ موفق |

## اجرا روی سرور ایزابل

```bash
python3 admin-fixes/fix-apply-config.py
```

وصله‌ها idempotent هستند و از هر فایل یک‌بار بکاپ با پسوند `.bak-mt`
می‌گیرند. پس از اعمال، کش مرورگر را با Ctrl+Shift+R بشکنید.

## آزمون پذیرفته‌شده (مرورگر واقعی)

۱. بدون تغییر معلق: دکمه در صفحه نیست.
۲. با پرچم واقعی `need_reload` در پایگاه‌داده: دکمه خودش ظاهر می‌شود.
۳. کلیک: تا ۱۴ ثانیه بعد دکمه مخفی می‌شود + اعلان سبز فارسی می‌آید.
۴. بارگذاری تازه: دکمه برنمی‌گردد و پرچم سرور `false` شده است.
